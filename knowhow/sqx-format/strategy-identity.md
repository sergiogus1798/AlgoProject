# Identity = SHA-256 of the canonical logic, not of the XML text
Since 2026-10-16 (encargo 76) `core.sqxfile.identity` hashes `canonical(xml)`: every `Param variable="true"` reference is replaced by its variable's value, the five slot variables (MagicNumber, the four `*Signal`) by their name, `Note`/`Description`/`Descriptions`/`Variables` are dropped, so are the attributes in `sqxfile.COSMETIC` and a `value` equal to the text; numbers go through `repr(float())`, attributes are sorted. So SQX writing a variable as a literal, reordering the variables (the WFM does), toggling `makeExternal`/`autoGenerated` or a signal's state, or a stamped description, keeps the identity; one parameter moved changes it. Known answers: `tests/test_identity_canonical.py` (the regex identity before it failed `wfm_reordered` and `inlined_variable`). Every identity computed before 2026-10-16 is another string: the store was re-keyed (`python3 -m core.store rekey`, map in `AlgoData/store/identity-map-2026-10.csv`); reports, raw and harvest folders still carry the old ones. ~1 ms per file (parse), was 0.2.
