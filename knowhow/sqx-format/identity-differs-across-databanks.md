# One identity runs from Results through SPP; only the WFM rewrites it — and the 2026-09-26 «0 shared» was the stripped attributes
Rule (rewritten 2026-10-11): `core.sqxfile.identity` is the same for one strategy in every databank of a project except `WFM`, which rewrites the parameters (its files are other strategies). Step-12 sisters differ too (fabricated file vs retested copy). A name alone is not a key: `MCR_All` drops the `Strategy ` prefix (`1.23.51`) and builds reuse names. Not: «identities never match across databanks» — that count (below, 2026-09-26) was taken before the `makeExternal`/`autoGenerated` strip. Pair by identity, or through `lineage.csv`; for `WFM` pair inside its databank.
🔬 2026-10-06 Measured on `Test_USDJPY_M30_doubleROCLong` after the `makeExternal`/`autoGenerated` strip: one identity in 17 databanks, from Results through SPP it does NOT change; only the WFM gives another (it rewrites the parameters). Step-12 sisters differ too: the fabricated file and its retested copy have other identities. The 2026-09-26 «0 shared» count was the stripped attributes. Pair inside one databank, or through `lineage.csv` (strategy, identity, mother), which `sqx.export.export_trades.lineage` now writes in every trades export; an empty mother is never paired (`core.store.late.mothers`).

🔬 2026-10-06 The judge no longer trips on it: when a fact's non-empty identity is not held by the cut databank, `pipeline/autopilot/judge.py::resolve(pop, found)` routes it to the file of the same name; facts without identity keep their key. On one stored run presence failures went 1,557 -> 0 and alive 140 -> 169; across 28 stored steps 0 verdicts moved for strategies whose identity did not change (`tests/test_autopilot_judge_identity.py`). Why: only the WFM rewrites parameters.

- Cause found 2026-10-06 (above): the strip. Original note: The gate keys by the BUILD identity by design (`studies/screening/gate/
