# `commission.use` is one {method, value} PER SEGMENT — the max-per-segment CONFIRMED broker, never one flat figure
Owner, 2026-09-29 — "aplica el máximo de cada a la hora de buildear y testear": SQX charges one commission method per TASK, and a project prices `build`/`oos1`/`oos2` on their own tasks, so `costs.commission.use` is `{build: {method, value}, oos1: {...}, oos2: {...}}`, never a scalar. Every asset still carries `brokers: {<name>: {method, value, unit, source, date, confirmed, note?}}`; `confirmed: true` only off the firm's own page or the owner's own statement (`source: "dueño, <date>"`), dated. `core.commission.per_segment(brokers, prices, point_value)` prices every confirmed broker in dollars at THAT segment's own median price and keeps, for each segment ON ITS OWN, the winner's OWN method and value — never converted into one flat unit, because a real `<Setup>` charges exactly what the winning broker declares. `sqx.projects.setups.sqx_settings` reads `use[segment]` directly; `one_setup` already flips whichever `<Method type=...>` it is given.

## Evidence
`core/commission.py` (`commission_usd`, `per_segment`); `core/assetdata.py` `sqx_settings()` (`use("commission")[segment]`); `core/assetwrite/brokers.py` (`set_brokers`, the only writer of the `brokers` table — `set_cost` writes `use`); `core/assets.py` `broker_table()`/`report()` render the per-segment table under the commission line; `core/assetcheck.py` `pending()` blocks on ANY segment's `value` still `None`, not on the field itself.
